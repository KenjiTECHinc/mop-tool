Design guidelines

Visual rules and components for the AI-assisted ticket platform. Light mode only. Written for developers and AI agents building the interface: follow the tokens exactly and add nothing that is not listed.

Principles

The assistant is home.

After login the user lands on the chat. Tickets, and for Admin the console, are one click away. The chat composer is the most prominent element on the page.

Purple means AI or the one primary action.

Accent marks what the assistant says, proposes or is waiting on, plus one primary button per view and focus rings. Never use it for decoration.

Quiet surfaces, no extra colors.

Only ink, stone and purple, plus tints mixed from them. Meaning is carried by shape, weight and text, not by new hues.

Only what the PRD includes.

No dashboards, boards, notifications or settings pages beyond the PRD. If a feature is not in the PRD, it has no screen.

Color

Two main colors and one accent. Everything else is a tint mixed from them with color-mix.

Contrast: ink on stone is 13.7:1. Accent on stone is only 3.9:1, so never set small text in the accent color. Use it for fills, borders and dots, with --on-accent text on top. Errors and destructive actions use ink fills with explicit text and an icon, not red. If you later want a semantic red, add it as one extra token.

Typography

One family: Chiron GoRound TC, a rounded sans that covers Latin and Traditional Chinese. Load weights 400, 500 and 700 only. Fallbacks: PingFang TC, Noto Sans TC, Microsoft JhengHei, system-ui.

Components

Buttons

One primary (accent) button per view or card. Secondary for the alternative, ghost for tertiary actions. Delete uses the ink-filled button and only appears inside a confirmation. Label with the exact action: Create ticket, Delete ticket, Save changes. Never Submit or OK.

Rules for AI agents building this

DoDon’t
Use the CSS variables below for every color, radius and font.Hardcode hex values, add new colors, gradients or drop shadows on cards.
Put the assistant chat on the home route and keep the composer visible on every page.Build extra dashboards, boards or settings pages.
Externalize all text for English and Traditional Chinese; test layouts in both.Hardcode strings, fix label widths or use all-caps labels.
Hide controls a role can’t use, and still show clear permission messages from the server.Show a disabled delete button to a Developer.
Render every assistant write through a confirmation card.Let a chat message change data without confirmation.
Meet WCAG AA: visible focus, keyboard access, 4.5:1 text contrast, labels on every input.Set small text in the accent color, or rely on color alone for status.
